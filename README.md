# Srochka-y-Tochka

# PRD: Лендинг «Олимпиада аналитиков 2026»

## 1. Цель проекта

Создать одностраничный продающий лендинг на русском языке для конкурса финансовых аналитиков **«Олимпиада аналитиков 2026»**.

Цель сайта — привлечь участников-аналитиков:

- профессиональных аналитиков;
- сотрудников брокеров;
- сотрудников управляющих компаний;
- сотрудников банков и инвестиционных домов;
- независимых финансовых аналитиков;
- авторов Telegram-каналов;
- инвестиционных блогеров;
- аналитические сервисы и платформы.

Главное целевое действие — нажать кнопку **«Подать заявку»** и оставить данные в форме обратной связи.

Сайт должен выглядеть как серьёзный профессиональный турнир инвестиционных идей, а не как любительский конкурс.

---

## 2. Общая концепция сайта

Лендинг должен донести мысль:

**«Олимпиада аналитиков 2026» — это публичный профессиональный турнир качества финансовой аналитики, где аналитик может получить независимую оценку, признание, продвижение бренда и денежный приз.**

Ключевые ценности для участника:

1. **Деньги** — призовой фонд 5 400 000 ₽.
2. **Признание** — публичное попадание в число лучших аналитиков рынка.
3. **Продвижение бренда** — дополнительное внимание к автору, компании, каналу или аналитическому сервису.
4. **Знак качества** — независимая оценка инвестиционных идей.

---

## 3. Формат сайта

Сайт должен быть одностраничным.

Основные разделы сайта:

1. **О конкурсе**
2. **Награды**
3. **Формат**
4. **Участие**
5. **FAQ**
6. **Идеи**

Важно: не создавать слишком много отдельных разделов.  
Призовой фонд и номинации должны быть внутри одного раздела **«Награды»**.  
Условия участия и выгоды участника должны быть внутри одного раздела **«Участие»**.  
Форма заявки должна находиться внутри раздела **«Идеи»** внизу страницы, но к ней должен вести отдельный якорь `apply`.

- премиальные финансовые сервисы;
- международные награды;
- финансовые турниры;

Не делать сайт слишком игровым, детским или любительским.

## 14. База данных заявок

### 14.1. Требование

Форма должна сохранять заявки в базу данных.

Предпочтительный вариант базы данных:

**Supabase**

Если проект делается в Lovable, использовать Supabase.

Если проект делается в Vercel, можно использовать:

- Supabase;
- Neon;
- Vercel Postgres.

### 14.2. Таблица

Создать таблицу:

**applications**

### 14.3. Поля таблицы

Поля таблицы:

- `id`: bigint, primary key, auto increment
- `created_at`: timestamp with time zone, default now()
- `name`: text, not null
- `status`: text, not null
- `link`: text, not null

### 14.4. Логика сохранения

При отправке формы:

1. Проверить валидность данных.
2. Сохранить заявку в таблицу `applications`.
3. Автоматически сохранить дату и время через `created_at`.
4. Показать сообщение об успешной отправке.
5. Очистить форму.

### 14.5. Просмотр заявок

Предусмотреть возможность будущего просмотра заявок:

- через Supabase Table Editor;
- через будущий защищённый route `/admin`;
- через отдельную будущую админ-панель.

На первом этапе полноценную админку делать необязательно, но структура должна позволять её добавить.
